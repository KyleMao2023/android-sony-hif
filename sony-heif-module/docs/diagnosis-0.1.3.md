# 0.1.3：微信同图共享与有界解码队列

## 依据与范围

用户确认 0.1.2 后相册几乎正常，微信仍有“图片加载失败”。16:17 的实际微信日志中，短时间出现多条 `another decoded image is still live`，同时有一张解码成功。这直接证明部分失败来自旧版单图准入的立即拒绝；不能据此排除微信输出 Bitmap 分配或其他入口的问题。

用户同意下一版采用“同图共享、有界排队”。本版保留单进程最多一张 RGB16 的约束和 0.1.2 原始流回退修正，不更换 Rust 解码器、不改变 HLG/像素变换，不修改 system 文件。

## 实现

- `native/decode_queue.*` 在进程内统一准入。输入长度/FNV64 筛选后仍比较全部字节，不用路径身份或仅哈希判定，避免错误复用。
- 同字节文件的在途解码和存活结果共享只读 RGB16；各 Router 保留独立行号及输出格式。相同输入的编码缓冲也归并为共享所有权。
- 不同图按准入顺序等待。最后一个共享句柄先调用 `sony_hif_free`，再清空活动任务并唤醒下一张，保证 Rust 原有 lifetime reservation 已释放。
- 解码完成到等待者取得引用之间，用短暂的强引用 bridge 保活；全部已登记调用离开后移除。最后一个读取者释放后不继续缓存大图。
- 最多 8 个不同任务（含活动任务）、64 个获取结果的调用、256 MiB 已准入的唯一编码输入。初始化阶段尚未准入的 Router 输入不在该额度内，应用输出也不在内，因此不是总内存硬上限。
- 后台排队 15 秒，Android 主线程排队 250 ms。超时移除该等待者，最后一位等待者离开的未开始任务被删除；不取消其他等待者、不强行打断后端。已有成功结果优先交付。长时间保留某图会使不同图的等待者最终超时。

Rust 的单图 reservation 仍为兜底。大图约 344.57 MiB 的 RGB16 不会因同图并发而复制八份；解码临时缓冲、编码输入和微信/相册 Bitmap 仍需内存。

## 测试与审查

先以模拟旧行为的后端运行共享测试，第二个同图请求断言失败，再实现队列。后端 stub 保留“最多一个活动对象”限制，验证真实占用至 free 的顺序。

9 项快速 Rust 测试通过；流/回退和队列测试通过。队列覆盖：同图对象身份与编码归并、8 个并发读取者、释放最后读取者后再开始下一图、三图 FIFO、队首过期推进、超时重试、一个等待者超时但另一个继续、后端失败恢复、任务/请求/编码字节额度恢复，以及句柄晚于队列析构释放。

独立并发代码审查未发现 Critical/Important 问题，建议的两个 FIFO/队首超时测试已补充并通过。审查范围是多个独立 Router 的共享队列，不保证同一个 Router 对象被并发调用。

### 真机并发对照

同一设备，探针先创建独立解码器，再在屏障后同时请求完整原图并读取所有 RGBA8888 扫描行。它不加载真实微信或相册，也不分配完整应用 Bitmap。

| 场景 | 0.1.2 | 0.1.3 |
|---|---|---|
| 420 同图 8 请求 | 1 成功，7 失败 | 8/8 成功，只执行 1 次后端解码 |
| 420/422/422 HLG 各 3 请求 | 未运行 | 9/9 成功，只执行 3 次后端解码 |

首次运行的同图总耗时约 3.2–3.4 秒；混合请求全部完成约 10.4 秒。这是一次功能验收，不是稳定性能基准。每次单图后端约 2–2.6 秒，其余包含排队和扫描行转换。

全部结果尺寸 9504×6336，完整 RGBA8888 FNV1a64 与旧版基线一致：

| 样片 | 哈希 |
|---|---|
| hif420.HIF | `1e746690d0587735` |
| hif422.HIF | `063810d9c54dbc1a` |
| hif422hlg.HIF | `444c433937951481` |

首次探针报告的最大 RSS：旧版同图 570028 KiB，新版同图 570672 KiB，新版混合 674272 KiB。探针仅持有各线程的一行输出，数据**不能代表微信的峰值内存**，也不能证明进程不再受内存限制。混合场景还保留了多张图的编码输入。

### 回归

- 交付模块经匿名 API 回调的 Zygisk 注册探针通过。
- 未登记代理虚表场景的真实 libheif 回退通过，确认收到原始流对象。
- 普通 HEIF 副本经原系统 AImageDecoder 回退成功。
- 三张原图经真实平台 AImageDecoder 的工厂接管路径成功，主尺寸正确、1584×1056 输出返回 0。
- ZIP/ELF 检查通过，22 项、AArch64、16 KiB 对齐、仅 libc/libdl/liblog/libm 依赖，适配器 CFI 与非 CFI 注册边界均保留。
- 设备临时探针使用的模块哈希与最终 ZIP 内模块相同，三张原图 SHA-256 保持不变。

结果与日志见 [evidence-0.1.3](evidence-0.1.3/)。完整私人故障报告未进入源码包。
