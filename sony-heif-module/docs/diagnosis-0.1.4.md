# 0.1.4：Creators' App 手动 Wi-Fi HEIF 导入扩展

交付 Sony HEIF Entry 0.1.4（ARM64 / Android 16）与 Creators HEIF Wi-Fi 0.1.0（LSPosed APK）。原生模块只增加 `jp.co.sony.ips.portalapp` 主进程白名单，保留 0.1.3 的后端、队列、资源限额与回退。Java 模块仅匹配官方 Creators' App **3.5.0 / 350607302** 的主进程。入口在 Application.attach 后查询实际版本；接口不匹配或安装失败时关闭功能并撤销已注册钩子。

## 行为与修正

7 个 Java 钩子负责：两处 `canCopy()`、手动文件展开来源记录、提前拒绝分支接管、下载 Runnable 作用域，以及两种尺寸读取。格式保持 HEIF，使用应用原有缩略图回调和后续传输/入库路径。一次性代理处理成功、失败、重复通知和同步异常，最多继续一次。

独立审查发现并修正两个 Important 问题：

1. 下载器构造参数不足以改变调用者保存的 2M 局部变量。现于当前 HEIF 下载作用域中让尺寸读取返回 Original，同时影响回调、下载器和真正的 `downloadFile()` 分支。全局设置不写入；嵌套非 HEIF、其他线程和异常后的读取保留原结果。
2. 自动导入也产生普通 `PtpPullFileToTransfer`。现要求文件对象来自确切手动 `PtpPullItem.getFilesToTransfer()`，用弱引用按对象身份记录；自动父条目展开后的 HEIF 文件仍走原拒绝路径。

USB、相机推送、自动/差异导入和其他版本均未开放。RAW+HEIF 组合仍遵循应用原有文件选择偏好，本模块不打开其他导入设置。

## 安装与用户验收

1. 用现有管理器安装 `/sdcard/Download/sony-heif-entry-0.1.4-arm64.zip`。
2. 安装 `/sdcard/Download/creators-heif-wifi-0.1.0.apk`，在 LSPosed 启用模块，作用域仅选 Creators' App。
3. 按当前管理器流程让模块进入新应用进程。临时 root 状态需保留；本次未安装、激活、强停或重启。
4. LSPosed 日志应有 `CreatorsHeif: installed 7 hooks for 3.5.0 manual Wi-Fi HEIF`。Wi-Fi 手动导入一张 HEIF，检查后缀、原图尺寸、放大细节；有相机卡原文件时核对 SHA-256。然后验证全局 2M 偏好下 HEIF 仍取原图，JPEG/RAW/MP4、取消和断连正常。

停用此 LSPosed 模块并进入新进程即可撤销格式扩展。原生模块可独立回退到 0.1.3。HLG 仍为近似 SDR 查看；60MP 解码成本和原有排队上限保持，见 [README](../README.md)。

## 实施决定记录

- 在用户指定的当前 D 盘检出中实施，保留受保护的 `.git`；代价是此轮更新不能自动提交。
- Windows 下用 PowerShell 和被忽略的 `.work/creators-heif-wifi` 保存计划账本/证据；代价是账本未提交前需保留该本地目录。
- 迁移后缓存 Rust 测试二进制仍含旧路径，测试脚本默认设置当前样片目录并保留显式覆盖；代价是完整样片测试仍需本地照片，解码器源码未改。
- 提取 InstallOnce 检查初始化生命周期，并用独立 app_process 验证实际 APK 反射契约；代价是它们无法证明 ART 激活或相机 GUI。
- 按真实 APK 控制流修正原计划的构造参数方案，并增加文件来源约束；代价是需要更多精确版本接口，失配时关闭功能。
- 激活、相机、字节身份、取消/断连与应用性能保留为用户验收；代价是交付后仍可能出现仅实际流程能发现的问题。
